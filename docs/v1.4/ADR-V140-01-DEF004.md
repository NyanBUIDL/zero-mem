# ADR-V140-01 — DEF-004 Knowledge-Space Resolution

**Status:** DRAFT (chờ maintainer chọn tại GATE-2)
**Date:** 2026-08-24 · **WP:** V140-02 · **Defect:** DEF-004
**Authors:** Builder (SCOUT impact-set + draft) / Maintainer (quyết định A/B)

## Context

DEF-004: grant kiểu `knowledge_space` được cấp đúng (AllowsScope mang
`allowed_knowledge_space_ids`, grants.py resolve từ `AuthorizedReadGrant`
target_type=`knowledge_space`), nhưng hàm `_scope_allows()`
(`src/access/authorized_read.py:176-179`) **trả False** cho mọi space-grant
vì `zm_meta` (event store) **không có cột `knowledge_space_id`** — không thể
validate row data → non-authorizing, fail-closed đúng nhưng chức năng chết.

Quan trọng (SCOUT phát hiện): đường corpus (`corpus_unit_search` →
`AuthorizedCorpusScope`) **đÃ HOẠT ĐỘNG** với knowledge_space, vì
`zm_corpus_units` có cột `knowledge_space_id` và scope được enumerate thành
tuple (profile, project, space). Vậy DEF-004 **chỉ ảnh hưởng event-store reads
(zm_meta / zm_relations / M3/M4/M8 path)**, KHÔNG ảnh hưởng corpus retrieval.

## Impact-set (Graphify code-only + corroborated source)

- `_scope_allows` `src/access/authorized_read.py:139` — chốt fail-closed space branch.
- Callers của `_scope_allows` (event path): `authorized_read.py:377/418/437/481/562/597` — tất cả là event/verification/hitl reads qua `zm_meta`/`zm_relations`.
- `zm_meta` DDL `src/storage/migrations/migrate_1.py:12` — hiện KHÔNG có `knowledge_space_id`.
- `grants.py:142` — space grant đã resolve vào `spaces` set → truyền tới `compose_effective_scope` → `scope.allowed_knowledge_space_ids` (đã đúng, chỉ nút thắt ở `_scope_allows`).
- `corpus/retrieval.py` `AuthorizedCorpusScope` — ĐÃ có ks column, không đổi.
- Migration chain: `CURRENT_SCHEMA_VERSION = max(MIGRATIONS)` (`migrations/__init__.py:38`); hiện cao nhất = migrate_12. Thêm migration = migrate_13.
- Tests: `test_m5_grants.py`, `test_m5_policy_rebuild.py`, `test_m5_linked.py`, `test_wp29_authorization.py` — candidate regression surface.

## Options

### Option A — Migration v13 column (schema-first)

Thêm `ALTER TABLE zm_meta ADD COLUMN knowledge_space_id TEXT` qua
`migrate_13.py` (additive, idempotent theo PRAGMA, giống pattern DEF-007
migrate_12). Điền giá trị: event-store rows thiếu ks → resolve từ derived
state (corpus units? hoặc null → global-read default). Sửa `_scope_allows`
branch 176-179 thành validate `row.knowledge_space_id` khớp `allowed_knowledge_space_ids`.

- **Storage cost:** +1 nullable TEXT column trên mọi zm_meta row (~event count). Thấp.
- **Rebuildability:** migration additive, replayable từ canonical JSONL (ADR-009). ✓
- **Migration risk:** THẤP — additive column, không break read path; cần backfill
  ks cho event cũ (có thể null → global-read sentinel giữ nguyên).
- **Token cost:** thấp — chỉ đổi 1 branch + 1 migration + backfill script.
- **Nhược:** zm_meta là event-centric, gán ks cho event không tự nhiên (event
  thuộc profile/project/trace, ks thường thuộc corpus resource). Có thể null nhiều.

### Option B — Resolution layer (no schema change)

Giữ `zm_meta` nguyên. Thêm layer ánh xạ `knowledge_space → resource ids`
từ derived state đã có (ví dụ: từ `zm_corpus_units`/`zm_corpus_sources` lấy
tập (profile,project,space) hợp lệ, hoặc bảng nhỏ `zm_knowledge_space_map`).
`_scope_allows` với space-grant → tra cứu layer để lấy danh sách
profile/project được phép, rồi validate row theo (profile,project) như hiện tại.

- **Storage cost:** bảng ánh xạ nhỏ (số space × số resource), hoặc 0 nếu tính
  từ corpus tables dynamically (nhưng tốn query lúc runtime).
- **Rebuildability:** layer là derived từ canonical → rebuildable. ✓
- **Migration risk:** TRUNG BÌNH — thêm module resolve, nhiều chỗ gọi hơn;
  không đụng schema nên an toàn với existing DBs (KHÔNG cần migrate).
- **Token cost:** cao hơn A — viết resolver + tests, phức tạp hơn 1 nhánh.
- **Nhược:** tách rời ks ra khỏi row data → authorization phụ thuộc derived
  index; nếu corpus index chưa build, space-grant không validate được.

## Decision

**CHỜ MAINTAINER CHỌN TẠI GATE-2** — không tự quyết (theo GATE-1 condition).

Gợi ý Builder (không binding): **Option A** ưu tiên vì (1) zm_meta đã có
profile/project/session, thêm ks là nhất quán với model hiện tại; (2) additive
migration rủi ro thấp, replayable; (3) token cost thấp nhất; (4) corpus path
đã chạy rồi nên A hoàn thiện sự đối xứng event/corpus. B giữ nguyên schema nhưng
phức tạp hóa runtime authorization.

## Consequences

- Sau GATE-2: implement theo phương án được duyệt (RED-first per DEFECT-REGISTRY).
- A → viết `migrate_13.py` + backfill + sửa `_scope_allows` + test space-grant authorizing.
- B → viết resolver module + sửa `_scope_allows` + test.
- Cả hai: chạy full suite (isolated HOME) 0 fail trước khi đóng DEF-004.
