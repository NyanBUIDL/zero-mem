## Design choices worth review

- Approval = `Memory._apply_approved_write` as the PROPOSER profile (so source `profile_id` matches how that agent's own shared writes look) with
  `authorize_write` skipped, plus an `approve` canonical event (proposer, approver, proposal id, source id, version, basis). No grant is created.
- Pending-proposal dedupe is per proposing profile only (cross-profile dedupe would leak existence). Duplicates from several profiles stay separate.
- Kill switch / fail-safe block approvals as well as proposals; reject / revoke / expire still work. Mode `off` blocks only new proposals.
- `allow_agent_proposals=false` refuses sources `agent` and `learner`; `source` is a label, not authentication (documented).
- Active TTL applies only to items committed by an approved proposal (latest approval time); owner-written memories never expire.
- `Settings.failsafe` sets `kill_switch=True` internally so every consumer fails closed without a second code path.
- Replay: incremental offset, byte needle pre-filter, torn tail never trusted, strict per-record validation, terminal states final, `MAX_REPLAY_EVENTS=200000`
  (overflow refuses new proposals).
- RED-first note: implementation and tests were written in one pass (not strictly test-first). To show the tests bite, three mutants were applied and
  caught: expiry filter disabled (`test_active_ttl_hides_approved_items_without_deleting_them`), `proposals()` leaking other profiles
  (`test_cross_profile_isolation_through_memory_apis`), dedupe key ignoring scope (`test_duplicate_pending_proposals_collapse_...`).
