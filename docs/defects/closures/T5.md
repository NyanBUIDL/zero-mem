## DEF-057 - no forget / lifecycle transition (closed here; the secret-sensitivity half was closed by T1/T2)

Cause: re-registering identical bytes with `lifecycle_status="deleted"` returned the old record, and projection ignored `deleted`.
Fix (smallest): `forget` appends a **tombstone version** (same `source_id`, different bytes, `lifecycle_status="deleted"`); the projection treats a
latest-version `deleted` source like a withheld one (`SOURCE_STATUS_DELETED = "deleted"`: never read, extracted or indexed; earlier units pruned by
the DEF-050 mechanism). Raw blobs of every version stay (AGENTS.md: never delete raw traces). `zero-mem upgrade`'s empty-projection guard no longer
counts forgotten sources (a store whose every source is forgotten has 0 units by design). A later `add` of the same text is a new version
(resurrection; the content-addressed `source_version_id` equals v1's, `supersedes` points at the tombstone).

Write path of every `add` / `ingest` file (`Memory._authorize` -> `_write_one` -> `_commit_source`): closed-schema validation + byte caps (text 256 KiB, file 16 MiB,
names, ids, provenance) -> `authorize_write` (private = own profile; shared = `knowledge_space_ids=[ks-shared]` only, needs a WRITE grant; devlog/project = `project_ids=[p]` only;
DEF-051 makes a combined profile+scope request a denial) with a canonical `policy_decision` audit event for DENY and grant-using ALLOW -> secret pre-scan of the raw bytes,
of the ref/name/provenance AND of every extracted unit (office containers are only visible there) BEFORE anything is registered; unreadable content is rejected, not stored ->
`corpus_write_lock(root)` (T2's re-entrant lock; never a raw `locked()`) -> fresh `registry.refresh()` -> `register_source_with_blob` (lifecycle `observed`, provenance
`channel/writer/profile/tool`, `custom_meta={"memory_type"}`) -> `project_source` -> commit. Registered-but-unprojected state (crash, projection error) is reported as
`error: projection_failed` and healed by repeating the same call (`unchanged` + missing projection => project).

Design decisions worth reviewing:

* **Defaults.** `scope` defaults to `private` (least privilege; `devlog` is always `project`); `ingest` defaults to `memory_type="fact"` as specified; the CLI mirrors the library.
* **Refs.** `mem://<type>/<name or sha256[:12]>`; files `file://<root dir>/<relative path>` (percent-encoded, NFC); devlog `mem://devlog/<project>/<YYYY-MM-DD>/<sha256[:8]>`: a refinement of
  the design table's "one source per day" so that several entries per day are all kept and re-adding the same text on a day is a no-op.
* **`recall`** = implicit request (own rows + all-NULL) merged with the `ks-shared` request (+ one optional project request), deduplicated by unit, sorted by score then ref; scores are per-request BM25
  (documented approximation across the two populations). English function words are dropped from the query unless nothing else remains (the old store did the same; see benchmark).
* **`context`** reads through the same authorized facade (metadata-only queries per type), groups units per source, budgets 35/25/20/20 % with unused room flowing down, never exceeds `max_chars`; skill
  descriptions come from the SKILL.md front matter of the already-authorized source blob, else the first paragraph.
* **Approval model** (ADR-V170-02): `agents grant-write` writes a canonical `operator_approval` event first, then the canonical WRITE grant whose `verification_ref` is that approval; the lookup is
  incremental and fail-closed; revoke writes both a grant revoke and an approval revoke. Verified end to end across `zero-mem upgrade` (derived rebuild) and `backup create/restore`.
* **`serve`** execs `python -m src.integration.m6.mcp_server --store-path <db> --profile-id <profile>` but refuses (exit 2, explanatory message) while that module has no `--profile-id`
  (checked by reading the module source), because an unpinned server trusts the caller's claimed profile (DEF-062, T6).
* **`status` command name.** `tests/unit/test_pkg1_packaging.py` and `test_pkg3_setup_doctor.py` pin `status` and `rebuild` (and the word ` start`) as NOT registered in `--help`; the memory command is
  therefore `memory-status`, and `serve` is described as "run the MCP server". No existing test was edited for this.
