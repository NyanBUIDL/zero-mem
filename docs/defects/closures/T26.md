|---|---|---|---|
| DEF-200 | High (macOS CI, 3/3 full-suite runs) | A lock file whose parent directory is missing/being created concurrently failed at once: `_open_lock_file` retried only `transient` errors, but a missing lock file (`NOT_FOUND`) or ancestor (ENOENT, reported as `UNSAFE_PATH`) is neither, so one concurrent proposer got `stream_busy: cannot lock the learning state (NOT_FOUND)` (also a lost proposal `17 == 18`). | Closed on Linux by fault injection; macOS CI to confirm |

## Fixes
- `src/storage/platform.py`: `PlatformStorageError.missing` (ENOENT on an ancestor); `_open_lock_file` retries `NOT_FOUND`/`missing` inside the same bounded (~0.5 s) window, then raises the original error. A parent that is a regular file (ENOTDIR) is not retried: fails fast. Generic `locked()` still never creates directories.
- `zero_mem/paths.py`: `ensure_lock_parent` (existing real dir untouched, missing one created private via `ensure_private_dir`, symlinks rejected, short retry).
- Called before taking the lock in `learning_lock`, `append_canonical_event`, `Provisioner._admin`, learner state, share `InviteStore`. Settings, workspaces registry, share identity, layout setup and eval harness already ensured their directory. Error text keeps the real cause (`stream_busy (...)`, `stream_unwritable (...)`).

## Tests
`tests/unit/test_t26_lock_parent_race.py` (15): NOT_FOUND injection x6 lock users (RED before: 11 failures), bounded give-up, late parent creation, file-as-parent fails < 2 s typed, symlink/mode safety, 6-process cold start (passes 30/30).
