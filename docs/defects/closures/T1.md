## DEF-051 - `authorize_write` own-profile + KS/project bypass

Cause: for a request naming the requester's own profile PLUS a project/knowledge space the base policy returned
`ALLOW_LOCAL_WRITE`; `_requires_grant` was true, but `_primary_target` is ambiguous with two dimensions, so `authorize_write`
fell back to returning `base` (the allow) without ever resolving a WRITE grant.

Fix (smallest): when the base decision is an allow but the request needs a grant, strip the requester's own profile from the
request and decide exactly like the project/KS-only request (`_without_own_profile`, 9 lines). Own-profile-only is untouched
(`ALLOW_LOCAL_WRITE`); `evaluate()` (M5.1 base policy) is untouched.

## DEF-049 - redactor misses vendor credentials that are not on an anchored line

Fix: `src/redaction/redactor.py` now detects, anywhere in a string (still fail-closed: the whole string is replaced by a
`[REDACTED:<rule>]` marker, as `_ASSIGN` already did):
- `vendor_api_token`: `sk-` + 20 chars (covers `sk-ant-`, `sk-proj-`), `AKIA`/`ASIA` + 16, `ghp_/gho_/ghu_/ghs_/ghr_` + 20+, `github_pat_`,
  `xox[abprs]-`, `AIza`, `sk_live_`/`rk_live_`, `hf_`; every prefix must start at a word boundary (so `task-...`, `risk-...` never match `sk-`)
- `jwt_token`: three base64url segments starting `eyJ`
- `authorization_header` / `bearer_token`: inline `Authorization: Bearer|Basic|Token <value>` and mid-text `Bearer <20+ chars with a digit>`;
  `$VAR`, `${VAR}`, `<placeholder>` values are not credentials
- `credential_url_userinfo`: `scheme://user:pass@host` anywhere (the old rule was anchored `^...`)
- `env_secret_assignment`: `export NAME=value` / `NAME=value` where a `_`-separated word of NAME is TOKEN/SECRET/KEY/APIKEY/PASSWORD/PASSWD/PASSPHRASE
  (UPPER-CASE names, or any case after `export`), value >= 6 chars; skipped for placeholders (`$`, `<`, `{`, `%`), code references (`os.environ[...]`),
  enum labels (`SECRET = "secret"`) and metadata tails (`*_PATH`, `*_FILE`, `*_URL`, `*_ID`, ...)
All existing detections are kept. Three rule ids were added to the explicit registry `supported_secret_patterns()`.
Every pattern is guarded to start at a token boundary so scanning is linear: 4 MB inputs (base64, one long run, `eyJ`+run, `a*N://`,
whitespace runs, ...) each scanned in 0.5-0.75 s.

New helper `src/redaction/prescan.py` (for use BEFORE a blob is stored): `scan_text`, `scan_bytes`, `assert_text_safe`, `assert_bytes_safe`
(raise `PrescanRejected`, a `RedactionRejected`/`ValueError`, message = fixed codes + rule ids, never the value). Bytes are decoded best-effort:
UTF-8 with replacement plus a NUL-stripped view that exposes ASCII credentials in UTF-16/UTF-32 text with or without BOM. Verdicts come from
`redact_payload`, so they always agree with `scan_extracted_text`. Compressed containers (docx/xlsx members, images) are not opened; callers
scan their extracted text.

`zero_mem/notes.py`: `_VENDOR_SECRET` removed; `NotesStore.add_chunks` rejects via `scan_extracted_text` only (central redactor).
`tests/notes/test_notes_store.py` unchanged and green.
