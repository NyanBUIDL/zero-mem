# T17 - closure evidence: review findings on PR #4

Branch `wt/t17` (from 7010ba2). Registry deliberately not edited. All four findings reproduced with a RED test on the unchanged code
(`tests/unit/test_t17_review_findings.py` run against a `git archive` of 7010ba2: 17 failed; for findings 2 and 4 the failures were the
asserted behaviours: text still recallable after a failed approval, the owner-written replacement missing from recall).

| Finding | Reproduced | Fix |
|---|---|---|
| 1 P1 learned types writable by agents | yes: `Memory.add(..., "rule", scope="shared")` and MCP `memory_add` created a recallable source | `LEARNED_TYPES`; `Memory.add` / `ingest` return `denied` / `learned_type_requires_proposal`; the owner uses `Memory._owner_add` / `_owner_ingest` (CLI `add`, `ingest`, `import-notes`); MCP enums omit the types and the toolset message points to `memory_propose`; Reviewer approval path unchanged |
| 2 P1 approval event append failure | yes: failing `approve` append left the text recallable while the proposal read pending | compensation in `Reviewer.approve` (new source forgotten; new version of a name replaced by a version with the previous text); retry idempotent (unchanged write); unresolved undo reports `approval_not_recorded` |
| 3 P2 learner state race | yes: 4 spawned processes x 25 keys lost keys | `_save_state` load-merge-replace under `src.storage.coordination.locked` (10 s bound) + `_fsretry` for the replace |
| 4 P2 expiry vs owner replacement | yes: owner `add` of an approved name stayed hidden | expiry applies only when the LATEST version has provenance `tool = approve`; `Reviewer.list` / `expire` agree |

Design for 1: an internal owner entry point instead of a caller-supplied string; the default `Memory.add` and the MCP layer cannot set it. Documented in
the runbook and ADR-V170-03 (agents must not get a shell that can run `zero-mem add`).
Design for 2: compensation rather than an `approving` intent event (no new replay state); a crash between commit and record is not compensated but a retry
completes it without a second version.

Existing pins changed (only where they asserted agents can write these types): tests in `test_t14_proposals.py`, `test_t15_brief.py`, `test_t15_mcp.py`
and `eval_harness.py` fixtures now write learned types through `_owner_add`; the MCP schema test asserts the enums omit them; `BASE_WRITE_CHARS` 4543 to
4489 (memory_add / memory_ingest enums lost three values).

Not changed: devlog `--from-git`, `import-notes`, `learn` (goes through propose) keep working.
