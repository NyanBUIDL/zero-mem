## 1. `Memory.forget` (DEF-067, DEF-068)

`forget` resolves the full id, an 8+ hex prefix or an exact `external_ref` among the sources the caller can READ only: its own private rows, global rows, `ks-shared` when it holds the read grant and projects it was
granted READ on - exactly the row-level scope `recall` retrieves under. Everything else is not there: `not_found` / `unknown_source` with no id, ref or version, identical (asserted field by field and as JSON) to an id
that does not exist, and no audit event is written for the probe. The candidates of an ambiguous ref are limited to readable sources, so two agents holding the same text privately each forget their own copy by the plain ref;
a readable shared or project source without the write approval is still `denied` with the grant hint. Tests (two profiles on one data root): `test_t8_forget_hardening.py`; the T6b tool test that pinned the old workaround
(`AMBIGUOUS_REFERENCE` for a ref that also named another agent's private copy) now pins the correct result, and a new tool test pins `AMBIGUOUS_REFERENCE` for a ref that is ambiguous among readable sources, without any foreign id.
Decision: an agent with a write-only project grant cannot forget what it cannot read (strict reading of "a source the caller cannot read"); the runbook says to grant the read too.

## 2. First-run lock (DEF-069)

`Layout.ensure()` (explicit and default mode) and `commands_setup.run()` (`zero-mem setup`) create everything under an exclusive lock on `<data root>/.layout.lock`; in default mode the configuration is still validated BEFORE any path
(and the lock file) is created, exactly as `zero-mem setup` always did (`test_a_validation_error_still_creates_nothing_in_default_mode`). A failure that looks transient (unexpected error, `unable to initialize derived store`) is retried
(up to 4 attempts) with a jittered back-off; validation errors are raised at once (< 0.3 s) and a lock held for a minute is reported as `setup lock is held by another process`. `memory_bootstrap.ensure_layout` stays as a one-line alias.
Tests: 6 simultaneous cold starts x 5 rounds through `Layout.ensure()`, `Memory.open` (spawned processes with a barrier), and through real processes released by a go-file: `zero-mem add` x 3 + `agents add` x 2 + `setup` (default root),
and 6 tool-set start-ups each adding a memory; 4 consecutive runs of the whole file (24 tests; 3 of them together with `test_t6b_bootstrap.py`) green, no flake.

## 5. `zero-mem devlog --from-git` (DEF-072)

## Decisions for the reviewer

* `memory_recall` hit keys follow the task text (`id, type, ref, score, text`); `scope` is dropped (the ref and type carry what an agent needs; a shared write is explained when it is denied). `add` keeps a `scope` echo because a scope typo is the one mistake that changes visibility.
* `forget` strictness (read, not write, makes a source visible) and the unchanged `denied` for a readable source without the write approval.
* The server module keeps `--tools all` as ITS default so that the pinned T6a / T6b surfaces do not move; only `serve` / `mcp-config` default to the memory-only set.
* `devlog --from-git` writes complete days only; the oldest day of a `--since` run is therefore complete even when REF is mid-day.
