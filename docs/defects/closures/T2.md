## Design notes and decisions (for the reviewer)

* **DEF-050**: only the latest registered version of a logical source is projected; any unit of that source not yielded
  by the current extraction (including a version whose extraction fails, is empty, or whose units are now rejected as
  secret) is deleted from `zm_corpus_units` and `zm_corpus_fts` in the caller's transaction. `project_*` never commits.
  `unit_order`/`page`/`parent_ref` are now refreshed on the upsert of a surviving unit id. Not handled here (outside the
  three files): rows in `zm_corpus_relations` that point at a deleted unit remain until the graph is rebuilt.
* **DEF-053**: `register_source`/`_update_record` run under `corpus_write_lock(root)` = `locked(<root>/.write.lock,
  exclusive)` + a per-thread depth counter, then re-read only the appended tail of the JSONL (same inode, larger size)
  or reload fully (inode changed / shrank). The registry constructor takes a shared lock for its read. **Integration
  note for T5/T6:** when `register_*` and projection must be one critical section, wrap them in
  `src.corpus.registry.corpus_write_lock(root)`, NOT in a raw `src.storage.coordination.locked()` on the same file
  (flock is per open-file-description; a raw lock held by the same thread would block the registry's own acquisition
  until it times out). Lock timeout is 30 s and is reported as `ValidationError("corpus_registry: write_lock_timeout")`.
* **DEF-058**: `project_source(conn, registry, source_id | CorpusSourceRecord, blob_store=None)`; a stale record is
  resolved to the registry's latest version so the derived state can never regress; unknown id -> `CorpusProjectionError`.
* **DEF-060**: statuses are persisted under the key `zm_projection` of the derived `zm_corpus_sources.provenance` JSON
  (no schema change, no new table; rebuild-deterministic, covered by a rebuild-equivalence test). `source_status` works on
  a read-only connection. `CorpusProjectionReport.as_dict()` is unchanged (4 keys); `as_dict(include_sources=True)` adds
  `source_statuses`. New statuses beyond the nine M10.2 outcomes: `rejected_secret`, `withheld_sensitivity`,
  `blob_unavailable`, `not_projected` (query-only). A secret-rejected unit marks the extraction result
  `contained_secret=True` (`_flag_contained_secret`; the dataclass is frozen so a marked copy is made) and the flag is
  persisted/reported per source.
* **DEF-057 (storage part)**: `sensitivity="secret"` sources get a `zm_corpus_sources` row (so the status is queryable)
  but are never read, extracted or indexed; earlier-version units are removed. The registry still cannot change the
  sensitivity of an already-registered identical-bytes version (needs a lifecycle operation, outside this task).
* **DEF-059**: the projection is staged in a private temp SQLite DB (no lock on the live connection), then one
  short write transaction (`BEGIN IMMEDIATE` + SAVEPOINT) drops/recreates the v10 corpus tables and bulk-copies the staged rows.
  Commits when it owns the transaction; joins the caller's otherwise. Verified with a separate reader process using the
  production reader path (`open_readonly`) under WAL: 0 empty / 0 partial / 0 errors; the same test failed before the fix
  with 139 of 176 reads empty.
