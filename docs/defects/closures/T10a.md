## DEF-074 - restore of a corpus-less backup left a live corpus unprojected (silent inconsistency)
Repro (`tests/unit/test_def054_corpus_root.py::test_restore_without_corpus_projects_kept_live_corpus_into_derived_db`):
backup without corpus, live `data/corpus` with one source, `restore --yes` -> `SUCCESS`, but `zm_corpus_units` = 0
(recall empty, `memory-status` needs_rebuild, doctor corpus WARN). RED: `assert 0 > 0`.
Decision (smallest correct fix): the live corpus that restore keeps is now projected. Default root: copied into the
staged data root (`staging/data/corpus`), validated, and used for the staged derived rebuild, so it is swapped
atomically with the DB (live corpus untouched until the swap; the old post-swap move becomes a no-op). Explicit
`ZERO_MEM_CORPUS_ROOT` without `--corpus-root`: read in place for the projection. A corrupt live corpus now fails the
restore before activation (`_validate_corpus_root`), fail-closed. No new result fields; no warning needed since the
state is now consistent. Files: `zero_mem/backup.py`.

## DEF-075 - `devlog --from-git` on a repo with no commits failed ("git log failed", exit 2)
Agent-hook use on a fresh `git init` repo errored. Now a no-op ("no commits to record", exit 0). `zero_mem/devlog_git.py`.

## DEF-076 - `import-notes` aborted on a deeply nested JSON line
A line of 200k `[` raised `RecursionError` (not a `ValueError`), aborting the whole import with "unexpected error".
Now skipped as `malformed_json`. `zero_mem/notes_import.py`.

## DEF-077 - `ingest ""` ingested the current directory; `import-notes --path ""` fell back silently
`Path("")` is `.`. Empty ingest path now exits 2 ("not found: empty path"); `--path ""` is no longer treated as unset.
`zero_mem/commands_memory.py`.

Tests: `tests/unit/test_t10a_review.py`, the DEF-054 test above.
