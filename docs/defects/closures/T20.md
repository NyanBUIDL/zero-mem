# T20 - peer sharing core: evidence and proposed defects

Branch `wt/t20`. ADR-V170-05, runbook `docs/runbooks/peer-sharing.md`. The registry (`DEFECT-REGISTRY.md`) was NOT edited; rows below are proposals.

## Proposed rows
- **DEF-140** (low, design): `Memory._read_requests` / `context` / `brief` have no notion of additional readable spaces; peer-imported spaces needed a
  separate `_peer_requests` merged only in `recall`. Consequence: imported peer content is deliberately absent from `context` and `brief`. Follow-up: label and
  admit it there (T21 or later).
- **DEF-141** (low): `ssl.SSLContext` cannot request an *unverified* client certificate and an SNI-triggered context switch does not change `verify_mode`
  (verified on Python 3.13); the pairing endpoint therefore peeks at the ClientHello. Any future refactor to a stdlib `http.server` + `wrap_socket` would lose
  the pairing endpoint. Pinned by `test_unknown_client_certificate_refused_after_pairing` and the pairing tests.
- **DEF-142** (low): `learning_settings._flat` / `settings show` enumerate sections by a hard-coded tuple; any new settings table is invisible until added
  (fixed here for `sharing`).
- **DEF-143** (info): `Provisioner` / `valid_id` forbid `:` in profile ids; the peer profile `peer:<id>` therefore only exists as an in-memory access
  request subject (never a stored grant), which is intentional but means `zero-mem agents list` never shows peers.

## Evidence
- Non-share suite: `/tmp/venv/bin/python -m pytest -q -p no:cacheprovider` (see the report); share tests: `/tmp/venv-share/bin/python -m pytest tests/unit/test_t20_*.py`
  (133 passed, Python 3.13) and the transport/pull files also on Python 3.11 (52 passed). Without cryptography: 56 passed, 4 skipped.
- Verified experimentally: TLS 1.3 handshake works with ECDSA P-256 and Ed25519 self-signed certificates (P-256 chosen for portability); client-certificate
  verification cannot be switched by SNI; unknown client certificates fail the handshake.
