## New finding T7-F1 (proposed registry entry; the integrator assigns the ID) - hidden rows decided the AND/OR fallback

Cause: `retrieve_corpus` ran the AND FTS query over the whole index and applied the authorized-scope filter afterwards. When any row of
another profile matched every term, the AND pass was non-empty, so the OR fallback was skipped for the caller and the caller's own
partially-matching rows disappeared; the answer for an authorized caller depended on whether unauthorized rows existed (an existence
oracle for hidden content that matches all query terms). The discovery cap had the same flaw (other principals' rows fill the window).
Severity: low-medium (information leak of a single bit per query, plus wrong results). Not caught by T3's `test_hidden_candidates_do_not_shift_scores`
because it compared scores, not membership.
Fix (smallest): the authorized scope and the closed metadata filter are part of the discovery SELECT, before the candidate window.

## Hand-offs / not done

1. **Real LongMemEval run** needs network access to `huggingface.co` (`xiaowu0162/longmemeval-cleaned`); command in `benchmarks/README.md`. Until then no real
   LongMemEval number exists.
2. **Large document stores**: on a 13k-unit store built from `docs/`, recall p50 is 31-46 ms (previous ranking 1-2 ms) and keyword self-retrieval p@1 is
   0.749 (previous 0.841). A per-memory-type ranking (chat-like vs files) is the obvious follow-up; not done.
3. `src/storage/platform.py::_digest_handle` hashes the whole derived database twice per `open_readonly` call (identity fence); other read paths that
   open per call (the MCP server's `corpus_search`, T6) pay a cost that grows with the database (28 ms per call at 13k units). `Memory` now avoids it;
   T6 should reuse the connection or relax the fence.
4. `src/access/authorized_read.py:1043` still defaults to `limit=100` when the caller gives none (T3 hand-off 2); not in T7 scope.
5. Result-time context expansion (returning neighbors beside each hit as `RecallHit.context`) was not implemented: it cannot change the ranked list, so the
   benchmark cannot justify it, and it would touch the result type T6b is wiring into the CLI and MCP tools.
6. Recency tie-break for devlog sources not implemented (no ground truth to measure it); ties break by `external_ref`, oldest first.
7. English-only stopwords (`Memory._search_text`) and English-only stemming; Vietnamese tone-mark matching still needs the FTS tokenizer option (T2/T3 hand-off 5).
8. BM25 parameters, the coordination exponent and the neighbor weight were tuned on LoCoMo only (validated on held-out halves of it).
9. `Memory.recall` scores of the private and shared sub-requests are still per-population (T5 hand-off 2): not changed, no benchmark covers a mixed store.
