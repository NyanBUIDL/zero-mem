# T13 - closure evidence for DEF-090 (proposed row; registry deliberately not edited)

## Proposed registry row

| ID | Severity | Summary | Status |
|---|---|---|---|
| DEF-090 | High (Windows only, ~1/3 CI runs) | Concurrent processes writing the same blob / same registry on one Windows data root crash: `BlobStoreError: path_escape_attempt` (TestDef053BlobStoreConcurrency) and `PermissionError: [WinError 5]` (TestDef053RegistryConcurrency). Follow-up of DEF-053. | Closed by T13 (simulated on Linux; Windows CI to confirm) |

## Root causes (verified by reading code)

1. `CorpusBlobStore._assert_within_root` called `Path.resolve()` on the blob FILE, which another process is concurrently replacing; on Windows that resolution is transiently unreliable, so `relative_to(root)` failed -> false `path_escape_attempt`. Fix: validate the 64-hex digest filename and resolve only the stable PARENT directory (must be exactly `<blobs>/<digest[:2]>`). Traversal, symlinked parent and non-digest names are still rejected.
2. `os.replace(tmp, target)` raised `PermissionError` (WinError 5/32) while another process had the destination open. The old fallback ("target already matches -> success") read the target with `read_bytes()`, which itself hit the sharing violation, returned False and re-raised. Also `get/exists/put` reads and the registry JSONL append/tail-read/`_update_record` replace had no tolerance. Fix: `src/corpus/_fsretry.py` (`retry_transient`, delays 5,10,20,40,80x5 ms = 475 ms total, `_sleep` patchable), retries only `PermissionError` or `OSError.winerror in {5,32,33}`; other errors (ENOSPC...) are never retried/masked. Persistent failure -> typed `BlobStoreError(replace_failed)` / `ValidationError(corpus_registry: replace_failed|read_failed|append_failed)`; temp files always removed.
