## What was built

Every adapter is stdlib only (no runtime dependency), registered in `adapters/registry.py::_default_registry`
with a distinct `FormatKind` (`MD CSV JSON DOCX XLSX PPTX IMAGE` added; `detect()` aliases are case/dot insensitive).
Text is passed through verbatim (adapters never sanitize); the only secret boundary stays `require_safe` in the
projection. Units are chunked to ~800 chars (`chunk_text`, linear time); ids are deterministic and unique per source.

| Format (`kind` hints) | Module | Units / ids |
|---|---|---|
| txt | `txt.py` | **paragraph** units (blank-line separated), `#L<start_line>` (+`.k` chunks); `order` = 1-based sequence |
| md, markdown | `markdown.py` | front matter `metadata` `#fm`; headings `#h<L>` (`parent_ref` = enclosing lower-level heading, ATX + setext); paragraphs `#p<L>`; fenced code `#c<L>`; pipe-table rows `#t<L>r<k>` as `col=value; ...` |
| csv, tsv | `tabular.py` | header `heading` `#h`; one `table` unit per record `#r<N>` `col=value; ...`; row cap + byte cap -> `partial` |
| json, jsonl, ndjson, chat | `json_chat.py` | chat: `#m<pos>` / `#c<k>m<pos>` (+ `#title` / `#c<k>` heading); `{role,content}`, `{messages}`, content-part lists, ChatGPT `mapping` tree (active branch via `current_node`), Claude export `chat_messages`, Claude Code transcript lines; plain JSON -> `#j<n>` flattened `path: value` packs; leaf/message/depth caps |
| docx | `docx.py` + `_ooxml.py` | `Heading N` / `Title` / `outlineLvl` (+ localized names via `styles.xml`) -> `#h<i>`; paragraphs `#p<i>`; table rows `#t<i>r<j>`; footnotes/endnotes/headers/footers |
| xlsx | `xlsx.py` | sheet heading `#s<n>`; one `table` unit per non-empty row `#s<n>r<row>` (`a \| b`); sharedStrings / inlineStr / numbers raw / dates raw / formulas = cached value; row caps |
| pptx | `pptx.py` | slide order from `presentation.xml`; title `heading`, shape text, table rows; `page` = slide |
| png jpg jpeg webp gif bmp tiff tif | `image.py` | OCR (injectable engine, else lazy `rapidocr_onnxruntime`, else `PIL`+`pytesseract`) -> `#o<n>` text units; otherwise `partial` + ONE `metadata` unit `#meta` (format, WxH from stdlib header parse, size, "ocr unavailable") |

Office guards (`_ooxml.py`): entry-count cap checked from the EOCD record *before* the archive is listed, total declared
uncompressed-size cap, per-member bounded read, DTD/entity declarations refused, no extraction to disk, encrypted members
refused, every failure -> `corrupt_source` with a content-free reason, never an exception.

`src/corpus/detect_kind.py`: `detect_kind(filename, content) -> kind` (magic bytes win over extension; zip members decide
docx/xlsx/pptx; text sniffing incl. UTF-16 BOM; unknown binary -> `"binary"`), and `iter_ingestable(path, allow_roots=None,
max_bytes=16 MiB, follow_symlinks=False, include_unsupported=False, max_files=100000)` returning a lazy walk of
`(relative_name, path, kind)` items (`.read_bytes()`), with `.skipped` / `.skip_report()` (reasons: hidden, excluded_dir,
symlink, outside_allowed_roots, symlink_loop, broken_symlink, oversized, empty, unsupported_binary, not_regular_file, unreadable,
max_files_reached, max_depth). FIFOs/devices are never opened; reads use `O_NOFOLLOW|O_NONBLOCK` + `fstat`.

`pyproject.toml`: `[project.optional-dependencies] ocr = ["rapidocr-onnxruntime"]` only; `dependencies` stays `[]`.

## End-to-end and real-data checks

- `tests/unit/test_adapters_projection_e2e.py` follows design section 1: `CorpusSourceRegistry` + `CorpusBlobStore` ->
  `SQLiteStore` -> `project_corpus` -> `GrantAdminService` READ grant on `ks-shared` -> `open_readonly` ->
  `AuthorizedReadService.corpus_unit_search`. Every format (txt, md incl. code/table, csv, tsv, jsonl, json chat, plain json,
  Claude export, docx incl. table, xlsx, pptx, png metadata, png with injected OCR) is found through the authorized path;
  an unauthorized profile sees nothing; a secret-bearing unit is rejected by the projection (`units_rejected_secret >= 1`,
  secret absent from `zm_corpus_units`, clean sibling unit still searchable) for txt, md, csv, jsonl, docx, xlsx, pptx;
  two independent stores project identical unit ids; re-projection is idempotent; corrupt/unsupported sources are counted in
  `extractions_failed` without breaking the pass.
- Real files (read-only, counts only): the repo's Word-authored spec `.docx` -> 532 units (99 headings, 75 parented, 186 table
  rows, max 729 chars); a real 1.2 MB Claude Code transcript -> 272 chat units; the repo walked with `iter_ingestable` ->
  1023 sources registered (md 557, txt 434, docx 1, json 30, jsonl 1; skipped: hidden 5, excluded_dir 25, empty 3,
  unsupported_binary 6) projected to 24,091 units, 5 secret units rejected, 1 extraction failure (an all-blank txt).
- Python 3.11 smoke of every adapter + `detect_kind` (3.13 is the test interpreter).

## Not verified / limits (honest list)

- OCR: no OCR library or tesseract binary exists here. The RapidOCR / pytesseract wrappers are only exercised against fake
  modules written from the documented API shape (`RapidOCR()(bytes) -> (result|None, elapsed)`, `get_tesseract_version()`,
  `image_to_string`); real engines are **[U]**. Injected-engine and degrade paths are tested for real.
- xlsx/pptx are only tested on hand-built (spec-faithful) fixtures; only the docx has a real Word-produced sample. Strict
  OOXML namespaces are accepted (matching is by local name) but untested. WebP lossy (`VP8 `) / lossless (`VP8L`) dimension
  paths are implemented but only `VP8X` is fixture-tested.
- ChatGPT/Claude export shapes come from documented structure + synthetic fixtures (the Claude Code transcript is real).
- docx: only `word/document.xml` (no alternate main part names), no text boxes / drawings / comments; xlsx dates stay serials
  (no number-format interpretation); pptx ignores notes, images, charts.
- Integration risk for the T2 merge: the e2e tests read `CorpusProjectionReport.{sources_projected,units_projected,
  units_rejected_secret,extractions_failed}` and `project_corpus(conn, registry, blob_store=...)` as they exist at `031222b`.
- Unit-id change for txt: single-line paragraphs keep their old `#L<n>` id; a multi-line paragraph is now one unit `#L<first>`,
  so its old per-line units (`#L<n+1>`...) become stale until the stale-unit cleanup (design gap 2, T2) lands.
- `src/corpus/__init__.py` does not re-export the new adapter classes (outside this task's scope); import from
  `src.corpus.adapters`. `ExtractionResult.contained_secret` is still never set (design gap 13).
- Real-repo projection took ~70 s for 24k units, while walking + reading + registering the 1023 files took 1.3 s; the
  projection cost is mostly per-unit work in `project_corpus` (secret scan, inserts), not file walking - input for T7
  (adapter-only timing was not isolated).
