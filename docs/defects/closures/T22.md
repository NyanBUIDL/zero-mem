# T22 - security review follow-up: panel session, `ui --open`, tombstone scope, invite code and identity key (evidence and proposed defects)

Branch `wt/t22` (base 86e6b9d). `DEFECT-REGISTRY.md` was NOT edited; rows below are proposals.

## Proposed rows
- **DEF-160** (medium, fixed): the panel session cookie was host-scoped, not port-scoped, so the browser sent it to every other service on
  127.0.0.1 / localhost. A hostile dev server the owner opened in the same profile could replay it from a non-browser client with a forged
  `Origin`/`Referer` and `Host: 127.0.0.1:<panelport>`, read the CSRF token with a GET and drive every mutation.
  RED evidence (old tree, `git archive 86e6b9d`): `GET /add` with only the cookie and forged Origin/Referer returned `200` (`assert 200 != 200`).
  Fix (design chosen): **no cookie at all**. The 256-bit session secret is the URL path prefix `/s/<secret>/...`; a path is origin-scoped, so a
  page on another port never sees it. Any request without the exact prefix (including `/`, `?t=`, a replayed cookie) gets a generic 404 with a
  bare page (no nav, no panel name); comparison is `hmac.compare_digest`. Every `href`/`action` and every `Location` is root-relative in the
  page code and gets the prefix at ONE choke point (`PanelHandler._send`), so no page can forget it; a crawl test asserts it for every page.
  `Referrer-Policy: same-origin` and `no-store` stay; mutations still need the per-session CSRF token and the Origin/Referer check; the
  request line is never logged (per-request logging was already off; failure logs print only the inner path). The banner prints the URL once and
  says history/bookmarks keep it. The one-time `?t=` exchange is gone, the link is reusable until the panel stops; idle timeout unchanged.
  No JavaScript needed (Linux/macOS/Windows identical). Trade-off: the URL is a bearer secret kept by history/bookmarks (documented).
  Tests: `test_t22_ui_path_secret.py` (cookie replay + forged Origin/Referer, no `Set-Cookie`, crawl of every link/form action, redirects,
  form POST to its action, bare 404), wrong/near-miss prefixes in `test_t19_ui_security.py`.
  Existing tests changed and why: `t19_helpers.Client` no longer logs in (no cookie exists; it prefixes every request path, `cookie=False`
  means an anonymous client); the "exchange / single use / cookie flags / 401" tests became "no cookie, 404 without prefix, reusable link";
  `test_t19_ui_cli` expects `/s/<secret>/`; `test_t19_ui_pages` matches the prefixed inbox link; `test_t21_ui_sharing` expects 404 instead of 401.
  XSS/escaping, CSP, header, size and concurrency tests pass unchanged.
- **DEF-161** (low, fixed): `zero-mem ui --open` passed the secret URL to `webbrowser.open`, visible in the process list. The flag is still
  accepted (compatibility) but ignored with a notice; the URL goes to the terminal only. Test: no `webbrowser.*` or `subprocess.Popen` call.
- **DEF-162** (low, fixed): `GET /v1/tombstones` listed refs of forgotten secret-sensitivity items and skipped the outgoing ref scan. The
  withheld-sensitivity filter now applies to tombstone candidates too, and refs are scanned like the manifest's. Items outside the grant were
  already excluded (pinned by a test). RED: secret-sensitivity ref and `sk-ant-...` ref were returned. Tests: `test_t22_tombstones.py`.
- **DEF-163** (low, fixed): `share join <code>` exposed the one-time code in the process list. Added `--code-file PATH` and `-` (stdin); the
  positional form still works and prints a warning (never echoing the code); the runbook and the invite hints recommend the safe forms.
- **DEF-164** (low, fixed/documented): `identity.key` is an unencrypted secret. Documented in `peer-sharing.md` (what a copy allows: impersonate
  this machine to owners, impersonate this owner to joiners; why not encrypted: no secret store without dependencies, unattended `serve`).
  New `zero-mem share identity rotate [--yes]`: new key pair, revokes every peer and its grants, forgets every owner (copies stay), burns open
  invites, audits `identity_rotate` (old/new peer id and counts; never key material). Tests: `test_t22_share_cli.py`.
- **DEF-165** (info): a running `share serve` keeps the old certificate until restarted after a rotation (documented: stop it first).
