Behaviour decisions (all documented in the runbook): types allowed by `injection.types` gate every section including rules and persona; no task means no matched sections; an explicit
`max_chars` overrides the setting up to the 8000 hard cap while enabled/types stay the owner's; fail-safe settings give reason `settings_invalid` (a third reason beside the two in the brief);
rules take at most 60% of the budget while anything else could be shown and the unused remainder returns to them (found with a 500-memory store where 40 rules filled the whole
budget and no gotcha ever appeared); `memory_brief` has no `project_id` (token budget); `memory_propose` results use the house `reason_code` key (the task text said `reason`) and the new
statuses `PROPOSED` (ok) / `REJECTED` (error).

## Tests and evidence

RED first: `test_t15_brief.py` failed on import (`BriefBundle`), `test_t15_cli.py` 11/11 failed (unknown commands), `test_t15_mcp.py` 18/18 failed before the implementation. Mutants applied and caught:
gating disabled (6 failures), expiry filter removed (2), rule share set to 1.0 (1; after strengthening the test), the safety suite itself catches a broken expiry filter and a broken kill switch
(`test_eval_safety_fails_when_an_invariant_is_broken`).

Real stdio subprocess tests (`test_t15_mcp.py`): default tool list is exactly the three read tools and within +450; `memory_brief` EMPTY with `injection_disabled` by default, then rules after the owner
enables injection for that profile in `settings.toml` (live, no restart), and another profile stays empty; spoofed identity rejected on `memory_brief` and `memory_propose`; `memory_propose` absent without the
flag/env, present with `--enable-propose`, `ZM_M6_ENABLE_PROPOSE=1`, both flags (7 tools); propose -> pending (not recallable, not in the brief) -> owner approves through `Reviewer` -> brief and recall include it;
the printed `mcp-config --enable-propose` registration launches a server with the tool.

Full suite (plain `pytest -q -p no:cacheprovider`): baseline at b086a0f `2 failed, 6429 passed, 14 skipped`; after T15 `2 failed, 6483 passed, 14 skipped` (+54 tests: 52 new, +2 parametrised guard cases; the same 2 root-only failures in `tests/unit/test_m9_6_hardening.py`).

## Not verified here / deferred

* Windows and macOS were not run (Linux, Python 3.13 in the suite). `eval safety` and the compile of every new module were additionally run on Python 3.11 and 3.12 here (zero dependencies). Windows-specific code: history trim uses `retry_transient` around `os.replace`,
  UTF-8 everywhere (including BOM-tolerant cases files), `O_APPEND` file creation with mode applied only off Windows, `realpath` of the temp store, no POSIX modes asserted in tests.
* No agent client (Claude Code, Codex, ...) was driven with the new tools; only the zero-mem stdio test client. No session-start hook is installed or generated (owner's choice).
* `memory_brief` over MCP has no project argument; a pinned-project option could be added if the budget allows.
* Matching is lexical: a task sharing no word with an item will not surface it (documented; `eval` is the detector).
