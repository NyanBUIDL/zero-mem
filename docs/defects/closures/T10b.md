## 3. Scale latency (DEF-076)

Details, tables and the rejected stopword experiment: `docs/benchmarks/RESULTS.md`, "T10b follow-up". Summary: neighbor lookup used the `duplicate_of` index
(full scan) and the discovery join built an automatic index per query; fixed with `+u.duplicate_of`, `CROSS JOIN` and a two-stage window
(`_neighbor_sql`, `_fts_discovery_sql`). 13.7k-unit store p50 30.6 -> 19-24 ms. LoCoMo A/B/C fingerprints identical to the pre-change values
(`67acb66a2455abe8`, `972f8f2058a3fb26`, `6ddd43ce16a38e80`), so hit@10 / recall@10 differ by exactly 0 (limit was 0.005); authorization code and the
scope/metadata predicates are untouched (same SQL predicates, same Python authorization filter). Guard tests: `tests/unit/test_corpus_query_plan.py`
(the neighbor guard failed against the old SQL first). Commits `ebea328`, plus the guard hardening commit.
