# T16 - closure evidence: deterministic learner (`zero-mem learn`) and hooks

Branch `wt/t16` (from b086a0f). Registry deliberately not edited. Feature work under `docs/plans/LEARNING-HARNESS-PLAN.md` / ADR-V170-03; no defect fix.

## What was built

* `zero_mem/learner.py` (extraction, parsers, pipeline, idempotency state), `zero_mem/commands_learn.py` (CLI), a 6-line registration in `zero_mem/cli.py`.
* `zero-mem learn --from-transcript | --from-git [--repo --since] | --from-hook | --from-text FILE|-` plus `--profile --project --dry-run --max N --json`.
* Sources: Claude Code transcript JSONL, generic chat JSONL / JSON array, plain `User:` logs, git commit messages, hook payload. Own part-flattener instead of
  `json_chat._flatten_text`, because that one keeps `tool_result` text, which must NOT be a user statement.
* Only user-authored text. Dropped: assistant turns, tool_result, `isSidechain` (sub-agent prompts), `isMeta`, `<system-reminder>`-style blocks, questions, hypotheticals (`if`, `imagine`, `nếu`), first-person
  self-talk ("I never said", "I'll make sure", "mình không dùng"), reported speech ("the docs say"), fenced / indented / log / traceback lines, sentences under 12 or over 300 characters or under 3 words, messages over
  4000 characters (pasted briefings), more than 5 candidates per message, secrets (the normal prescan) and `safety.deny_patterns`. Weak cues (make sure, instead of, must, should, thay vì, phải) count only with a
  durable marker (every, whenever, before committing, this repo ...), so one-off tasks ("make sure the tests pass") are not rules.
* Commits: agent-written commits (Co-Authored-By Claude/Codex/..., "Generated with", bots) are skipped (self-report must not become a proposal); commit text is checked in `strict` mode (cue in the first two words, no weak cues), bodies are unwrapped.
* Types by cue (decision > gotcha > rule), scope shared (project-wide words) / private (personal-style words or none), name = up to 6 content words + 6-hex hash of the normalized text (stable), canonical text (no trailing punctuation differences) so
  repeats merge in `Memory.propose` and raise `seen`. Evidence `[<project>:<session>#L<line>, quote<=200]`.
* Settings: mode off / kill switch / invalid settings: nothing is done and the reason is printed (`disabled` in JSON); the daily limit stops the run (`stopped: daily_limit`, the rest stays unprocessed for a later run); `--max` default 10, hard cap 100;
  time budget 30 s (hook 10 s). Idempotent via `learner-state-<profile>.json` (processed `session#line#sentence-hash` keys, bounded to 50 000, atomic replace); dry-run writes and remembers nothing.
* `--from-hook`: reads at most 1 MB of stdin, catches everything except Ctrl-C, prints nothing, always exits 0 (bad JSON, missing / non-file path, unreadable transcript, refused settings: all silent).

## Evidence

Tests: `tests/unit/test_t16_learner.py` (24 tests: quality, parsing, CRLF, idempotency, seen counter, dry run, cap, daily limit, off / kill switch, secret never printed, from-text / stdin, from-hook malformed payloads, from-git, sidechain autodetect trap).
RED first: the file was written before any implementation (`ImportError: cannot import name 'learner'`). Fixtures were written BEFORE the cue tables were tuned: `tests/fixtures/learner/messages.jsonl`, 72 labeled user messages (EN and VI; 31 positives
rule / gotcha / decision, 41 negatives: questions, code / log / traceback pastes, assistant-looking text, hypotheticals, "don't worry", "never mind", chit-chat, a secret-bearing rule, VI false friends such as "phải rồi", "không dùng được", "đừng lo").

Type accuracy on true positives: 100% in both sets (rule / gotcha / decision). The gate in the test is precision >= 0.90 on both sets and recall floors of 0.5 / 0.4.
Caveats: 72 messages is small (one false positive moves precision by ~7 points); the fixtures and the patterns have the same author, so real-world numbers will be lower; Vietnamese without diacritics is not matched.

### Real data on this machine (read-only; nothing copied into the repo)

* This repository's git history, `--from-git --dry-run`: 83 non-merge commits in the window, 82 skipped as agent-written, 1 human message, 0 candidates. Before the agent-commit skip and strict mode, an ad-hoc run over all
  commit text gave 11 candidates, ALL false positives: descriptive prose ("Days are always written whole", "... can never be read as an option", "never commits"), partly from hard-wrapped lines cut into fragments. That is why commits use strict mode
  and unwrapping; after it the same commit text yields 0 candidates (the one "Days are always written whole" sentence was still matched at first and is dropped by the two-word rule).
* `~/.claude/projects/**/*.jsonl` (5 session transcripts + 22 sub-agent transcripts): the 22 sub-agent files yield 0 messages (all `isSidechain`). Defect found here (fixed before commit): the first implementation fell back to the generic
  chat parser when the Claude parser found nothing, which wrongly read sub-agent prompts (written by an agent) as user statements and produced 3 to 5 candidates per file; the generic parser now ignores Claude Code records
  and a test pins it. Of the 5 session transcripts, 3 are my own verification sessions (planted rules: all found, 0 false positives); the long orchestration session (22 user turns, mostly relayed task briefings) gave 2 candidates:
  1 plausible repo rule ("defects must be registered ... before fixes"), 1 false positive (a one-off "Next steps: ..." task line). Task briefings are the main false-positive class on real data; the 4000-character cap and per-message cap of 5 exist for them.
* No secrets appear in any output above (secret sentences are dropped before reporting; the test pins that the token never reaches stdout / stderr).

### Real CLI verification (Claude Code 2.1.287, isolated data root, a `zero-mem` shim on PATH)

`claude -p ... --setting-sources project --settings <hooks>` ran both the `Stop` and the `SessionEnd` hook, each piping the payload into `zero-mem --profile claude-code learn --from-hook`. The payload keys seen: Stop = `session_id, transcript_path, cwd,
scratchpad_dir, prompt_id, permission_mode, effort, hook_event_name, stop_hook_active, last_assistant_message, ...`; SessionEnd = `session_id, transcript_path, cwd, scratchpad_dir, prompt_id, hook_event_name, reason`. Result: 2 pending `source: learner`
proposals (one Vietnamese: "Tu gio luon viet test truoc khi viet code" as rule/shared; "Don't use print for logging" as rule/private), `seen` 1 after both hooks (idempotent), a manual `learn --from-transcript` afterwards: `skipped_processed 2`, created 0.
An earlier run in `proj` (two real prompts with the same text in one transcript) correctly gave `seen: 2` (two genuine statements). NOT verified: Codex / Hermes / OpenClaw (binaries not present here; documented as unverified), interactive sessions, hook timeouts, Windows / macOS.
