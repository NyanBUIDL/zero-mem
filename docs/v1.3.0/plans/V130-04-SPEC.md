# V130-04 SPEC — Temporal read integration: B29 (M8.4) → EvidenceSet

**Finding nguồn:** `docs/v1.3.0/analysis/P1-04-temporal-evidence-integration.md`
**Depends:** V130-02 | **Gate:** G0→G3

## Contract

### Input
`build_evidence_set(...)` / `RouterRequest` nhận thêm `as_of: Optional[str] = None`. Chuẩn hóa qua M8.1 `normalize_timestamp`; malformed → fail closed (TemporalError/QueryError), không nuốt exception.

### Behavior (Option A — annotation-only)
Khi `as_of` có giá trị: SAU khi EvidenceSet validated, với TỪNG resource đã authorized trong set, gọi `read_temporal()` (M8.4, descriptor authorization-first hiện có). Kết quả gắn vào field MỚI additive:

```python
EvidenceSet.temporal: Optional[EvidenceTemporalInfo]  # default None
# EvidenceTemporalInfo: per-resource {resource_id, valid_at_as_of,
#   history_count (<= MAX_HISTORY_VERSIONS=20), superseded_by (provenance verbatim)}
```

KHÔNG loại item, KHÔNG đổi selection/order/budget. Stale/superseded chỉ được HIỂN THỊ.

### Invariants
- Authorization-first: resource không authorized không xuất hiện trong temporal info.
- Fail-open đúng pattern M8.3 enrichment (`evidence_builder.py:366-374`): lỗi temporal engine → EvidenceSet giữ nguyên, temporal=None.
- Không tự nâng claim; không chọn truth by recency; NULL time không thành epoch/infinity (M8.1).
- Không as_of → EvidenceSet byte-giống hiện tại.

## Acceptance criteria
1. as_of hợp lệ + fixture zm_temporal_index → temporal info đúng per-resource.
2. as_of malformed → fail closed ở tầng request.
3. Không as_of → regression byte-giống.
4. Resource unauthorized → vắng khỏi temporal info (leak test).
5. Lỗi temporal engine → set nguyên vẹn, temporal=None.
6. history_count ≤ 20; superseded_by chỉ provenance.
7. Dataclass roundtrip cũ→mới→cũ serialization OK.
8. Full suite ≥ baseline; security/failure tests (G3) cho authorization leak.

## Migration plan
Không DB migration (zm_temporal_index đã có migrate_9). Dataclass evolution additive có test roundtrip.

## Rollback plan
Revert WP; field additive nên rollback không phá serialization cũ.

## RISK
- N+1 gọi read_temporal per item → bound bằng số item trong set (≤8) + MAX_HISTORY_VERSIONS; đo runtime trong V130-05.
- Phụ thuộc schema ks của V130-02 cho authorization seed đúng.
