## Contract

### Schema (migration 11, additive)
```sql
ALTER TABLE zm_meta ADD COLUMN knowledge_space_id TEXT;
CREATE INDEX idx_zm_meta_ks ON zm_meta(knowledge_space_id);
```
Đăng ký trong migrations runner sau migrate_10; ledger version 11; down = drop index + drop column.

### Semantics
- Ingest điền `zm_meta.knowledge_space_id` từ envelope `knowledge_space_id` (đang có sẵn ở capture path); thiếu → NULL.
- **NULL policy (D-2026-08-22-03, user-approved):** NULL = unscoped = visible theo global-default-read. KHÔNG deny-by-default. Mọi thay đổi hướng deny là NEEDS DECISION ngoài v1.3.0.
- Filter exact-equality: `QueryRequest` thêm field optional `knowledge_space_id`; filter set → chỉ match event cùng ks (NULL events bị loại khi filter ks cụ thể). Không filter → NULL events hiện bình thường (global-default-read).
- Enforce trên CẢ `search_text` (qua `_build_where` dùng chung) và structured query.
- `ZM_META_COLUMNS` thêm cột mới (vị trí cuối) → cursor fingerprint tự bao gồm ks filter qua req; kiểm chứng test 6.
- Rebuild path (`canonical_replay.py`, recovery) tái tạo cột từ JSONL envelope.

### Spec Note (master spec L148)
Master spec nói "một trace có thể thuộc nhiều knowledge space". Biểu diễn vật lý zm_meta là single-value theo D-01 (toàn bộ derived schema đã duyệt là single-value); đa-space quan sát vẫn ghi zm_scopes như hiện tại. Multi-value zm_meta nếu cần thật = NEEDS DECISION riêng.

## Acceptance criteria
1. Migration: fresh DB có cột + index; DB v10 fixture → up 11 OK, ledger ghi 11; down 11 sạch; migration test có upgrade-path thật.
2. Ingest envelope có/không ks → cột đúng/NULL.
3. Rebuild từ JSONL → cột tái tạo identical (so kết quả query).
4. `search_text` với `req.knowledge_space_id="ks-a"`: chỉ hit ks-a; ks-b và NULL bị loại dù MATCH khớp.
5. Search không-filter: event NULL-ks XUẤT HIỆN (test bắt buộc D-03); không leak ks-b vào query ks-a.
6. Cursor pagination với ks filter không leak xuyên trang.
7. Full suite ≥ baseline 3378 passed / 0 failed.
