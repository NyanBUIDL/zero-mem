## Deterministic result expectations

- Structured: every filter returns exactly the events whose `zm_meta` column equals the value; combined filters AND.
- Pagination: full deterministic result == concatenation of pages (no dup/skip); final page `next_cursor=None`.
- FTS: `search_text("alpha")` deterministic by `(created_at, event_id)`; `search_filtered` AND-composes.
- Relation/scope: explicit edges only; deleted targets excluded; knowledge-space returns mapped events.
- Verification/lifecycle: exact filters; claim-not-fact preserved; conflict/superseded verbatim.
- Error contract: each invalid input → fixed code; raw SQLite text never escapes.
- Read-only proof: all snapshot fields equal before/after.
- Secret safety: secret substring absent from all serialized surfaces.
- Determinism: repeated queries byte-stable in result IDs/order/cursor.

## Performance benchmark design

- Deterministic corpus (~200 events, temp, isolated store) with sanitized FTS content + relations.
- Measure (median + p95 over ≥20 iterations, time.perf_counter):
  - exact `get_event`; exact `get_trace`; indexed project/profile filter; combined structured filter;
    `search_text` (when FTS5 available); `get_related`; first-page pagination (limit 50); subsequent-page pagination.
- Record corpus size, query count, SQLite version, FTS capability. Baseline only — flag any pathological full-scan
  where an approved index exists (none expected). No cache added.
